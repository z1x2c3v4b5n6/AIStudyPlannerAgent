# C-6 Learning Path 生成质量评估

C-6 通过生产 Learning Path 服务回放固定响应，测量数据和评分规则能否区分输出结构、业务合法性、知识覆盖与前置顺序。真实模型对照是可选实验。本轮没有调用 DeepSeek，固定响应预先写入，因此三组差异反映回放设定，不能当作 RAG 改善真实生成的证据。

## 复跑与输入

从仓库的 `backend` 运行：

```sh
mvn -Dtest=GenerationEvaluationTest,GenerationRubricTest test
mvn clean test
mvn package -DskipTests
```

报告写到 `target/generation-evaluation-replay.json`，包含组内指标、每次尝试的原始响应、校验错误、时长、实际注入文本和人工参考事实。默认测试仅使用本地知识包及固定输出。

`src/test/resources/evaluation/generation/cases-v1.json` 固定八条学习请求和评分依据。每条包含等级、目标、主题别名、前置边、禁止词、人工核对事实及 Oracle 条目。固定日期为 2026-01-01，周期四天，每天 60 分钟。报告记录数据集和回放 SHA-256。评分变动应提交新版本并在运行前冻结，历史报告保留原版本。加入真实模型对照前，先固定模型、参数、案例、阈值、人工评分协议和采样次数。

| 组 | 上下文 |
|---|---|
| Baseline | 空上下文 |
| RAG | C-4 真实查询构建、领域识别、Top-8 检索及现有格式化 |
| Oracle | 人工选定的知识条目。Kafka 案例使用人工补充资料 |
| Stress | 在 C-4 候选前插入一条冲突或无关资料，仅用于两条压力案例，独立统计 |

三组调用生产提示词和 Learning Path 服务，保持相同请求、模型配置和业务校验。运行器断言首轮与重试提示词按生产规则构建，并检查实际上下文和同组用户请求。Stress 同样经过现有 Top-8 容量和 6000 字符格式化限制。评估只生成草稿，不访问业务数据库。

## v1 指标

- **输出结构合法率** 使用严格 JSON 字段形状判定，检查必需字段、值类型、重复字段、额外字段与尾随内容。生产解析器可能接受 Markdown 包裹或做类型转换，因此结构分与业务通过率分别统计。
- **业务通过率** 使用生产 parse 和 validate 检查首轮，同时报告实际服务走完生产重试后的最终通过率。
- **关键知识覆盖** 按预期主题数加权。主题标题匹配案例别名记为覆盖。未解析的输出计为零覆盖。
- **前置关系** 按预期边数加权。两个节点都需出现，后续节点必须排在前置节点之后，其 prerequisite 字段也必须能引用前置主题。
- **重复率与未识别主题率** 用可解析节点作分母。主题规范化后重复出现的第二个及后续节点计重复。白名单外主题计为待复核节点，作为无依据内容的筛查代理。合法扩展可能被计入，错误断言也可能藏在已匹配主题里。
- **禁止内容** 在标题、摘要、阶段、目标、方法、验收标准、前置及原因中扫描禁用短语。否定句、引述和同义改写需要人工核对。
- **空上下文稳定性** 同时报首轮和最终业务通过率，分母是实际注入为空的案例。没有样本的指标显示为空值。固定回放只能验证空上下文链路；模型波动需要真实重复采样。

C-4 在六条有上下文的案例中均返回了人工参考集合之外的条目。报告逐条记录这些 ID，并标为待复核。人工参考集合给出核心评估目标，并未穷举所有可用知识，因此额外条目数量不能直接作为误召回率。

## 人工评分 v1

以最终响应为单位，两位评阅人独立评分。先隐去实验组，评阅准确性与教学合理性；再提供实际注入文本用于依据评审。每个分值都记录支持或反驳的具体句子、知识条目或人工参考事实。输出不可评分时登记原因。Baseline 空上下文的上下文 Faithfulness 记 N/A，仍评准确性和教学合理性。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 事实准确性 | 存在会误导后续学习的事实或机制错误 | 主线正确，存在细节缺漏或模糊表达 | 关键机制与人工参考事实一致，能解释边界 |
| 上下文 Faithfulness | 将无关或冲突资料作为可靠依据，或把资料未支持的断言归给资料 | 主要断言有依据，部分依据不足或范围过宽 | 实质性引自资料的断言均能定位支持证据，并正确处理冲突 |
| 教学合理性 | 顺序阻碍理解，难度或练习明显脱离学习目标 | 主线可执行，局部依赖、难度或验收目标欠清楚 | 符合当前水平、周期和目标，依赖清楚，练习与验收可执行 |

保留两份原始分和仲裁理由，汇总每一维度的样本数、均分、分歧及一致率，同时记录显著错误计数。固定回放只报告确定性指标，本次没有人为其打分，也没有启用 LLM-as-Judge。

## 可选 DeepSeek 实验

仅在本地显式启用。以 PowerShell 为例，预先在环境中安全设置 `DEEPSEEK_API_KEY`，然后在 `backend` 运行：

```powershell
$env:GENERATION_EVAL_ALLOW_PAID = "true"
mvn "-Dgeneration.eval.live=true" "-Dtest=GenerationEvaluationTest" test
```

默认模型 `deepseek-v4-flash`，temperature 0.2，最大输出 2500 tokens，使用生产 DeepSeek 配置。可用 `GENERATION_EVAL_MODEL` 记录明确的模型选择。运行器在 CI 中拒绝启用。单次实验含 26 个初始请求，生产业务重试最多再发起 26 次模型网关调用。底层客户端传输重试可能增加 HTTP 请求次数。报告位于 `target/generation-evaluation-live.json`，含模型参数、网关调用数、供应商返回的输入与输出 token 数和计时。未返回 token 用量的响应单独计数。费用按实际模型、输入缓存和账单价计算，报告不估填未知费用。离线模式调用模型 0 次，供应商费用为 0。

## 采用证据

要回答生成是否改善，应对冻结案例运行配对、多次的真实模型生成，记录首轮、重试后、成本和分歧，并按任务类型查看基准与 Oracle 差距。八条案例适合管线回归和故障诊断，真实结论需要更大的独立样本和盲评。Oracle 使用人工选材，仍可能发生生成遗漏或错误，结果需与其他组采用相同评分规则。
