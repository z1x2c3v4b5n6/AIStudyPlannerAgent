# C-8 Agent Workflow 与可靠性

在 AI 助手的「工作流」模式输入自然语言。服务端识别四种受支持的学习意图，构建有界节点图，并在每一步后提交 MySQL 检查点。普通聊天仍使用 C-7 的 Spring AI 工具循环与当前 C-4 知识检索。

## 持久状态

| Flyway | 内容 |
|---|---|
| V5 | `agent_session` 保存会话文档、归属、版本和时间索引。 `agent_action_receipt` 用动作 UUID 作为唯一幂等键，保存已提交操作及结果。 |
| V6 | `agent_workflow` 保存节点图和执行结果，通过外键绑定会话。删除会话同时清理工作流。 |

聊天会话保留最近 30 条消息，模型最多回看 12 条、4000 字符。应用限制工具参数、单条结果及发送给模型的消息体积。模型调用不占用数据库事务。聊天以版本号防止覆盖并发请求，会话闲置两小时过期。新建会话时分批清理过期超过七天的会话和 30 天前的执行凭证。当前没有后台清理调度，低流量环境可能延迟清理。消息和提案随应用数据库一起备份。

确认使用账号范围内的行锁。业务写入、成功凭证和终态在同一事务内提交。崩溃发生在提交前时，数据库回滚该事务，保留原待确认提案。提交成功后再次确认只会读取已有状态。对于已有 EXECUTING 文档，检查同账号、会话和摘要下的凭证，有凭证则恢复已执行状态，否则标记失败待人工核对。发送、确认、取消、删除及工作流控制从当前登录身份取账号。

## 执行与授权

支持 START、PLAN、TOOL、CONDITION、APPROVAL、RESULT、END 和 ERROR 节点类别。节点有输入、依赖、状态、输出、错误、尝试次数和开始结束时间。发布前验证顺序、依赖、条件引用、工具允许列表，最多 16 个节点。条件为假时跳过受保护节点，并生成说明。存储行锁使并发推进串行化，已完成步骤不再调度。

30 分钟工作流期限和 10 分钟审批期限在读取或推进时检查。数据库步骤采用短事务，写入和对应工作流检查点原子提交。模型步骤先记录租约，在事务之外调用现有 Learning Path 生成与校验，再按版本提交结果。应用重启后，租约过期的模型读取可以显式恢复，最多两次节点尝试，每次沿用原生成器的重试。取消后拒绝提交迟到的模型结果或调度后续步骤。重试适用于可恢复的读取和模型异常，已审批的写入失败需要重新规划。

改期预览展示明确的任务、旧日期、新日期和时间预算。批准仅覆盖预览中的任务调整。计划和学习路径草案仍进入现有业务页面，由用户在该页面确认保存。时间冲突和任务版本在应用改期前重验。任务批量改期和检查点在同一事务中完成，后续草案失败会保留并显示已提交变更。其他系统同时安排的日计划仍由现有计划流程校验。应用没有通用补偿或跨工作流时段预占。

## 四类流程

| 场景 | 执行内容 |
|---|---|
| A，本周未完成任务 | 查询本周计划日或截止日在本周的任务，将逾期、优先级和截止时间用于排序。 |
| B，明天两小时重新安排 | 读候选及实际每日计划，检查时段冲突，按预算选任务，展示日期差异，获批后更新并生成日计划草案。 |
| C，学习进度 | 读取任务、记录、统计及已有路径，输出实际统计和逾期件数。 |
| D，一周 Spring Boot | 读取科目、任务与本地知识，调用已有 RAG Learning Path 生成与校验，等待草案交接批准。 |

各场景有数据库持久化测试及现有 Service 数据夹具。受支持词组、相对日期、ISO 日期和常用时长由 Java 规则解析，任意多意图组合和任意图生成超出当前范围。每日计划默认从 09:00 开始，提到下午使用 14:00，可指定 HH:mm。长期路线默认七天、每天 60 分钟。任务候选最多 25 条，统计和工作流结果展示样本范围。

## 评估

在 backend 中执行 `mvn -Dtest=AgentEvaluationTest test`。逐案轨迹与错误分类生成在 `target/agent-evaluation-v1.json`，用例固定在 `cases-v1.json`。离线包含 8 个脚本式模型响应和 8 个持久工作流场景。相对于 C-7 的单轮测试，不用新的脚本回放准确率代替历史真实模型基线，C-7 也没有可直接对照的持久工作流成功率。

| 指标 | 本地离线结果 |
|---|---:|
| 工具选择准确率 | 6/8 |
| 参数有效率 | 6/9 |
| 执行成功率 | 15/21 |
| 工作流完成率 | 4/8，含主动拒绝、取消和拒绝访问 |
| 未授权写入、重复执行 | 均为 0 |
| 人工授权遵从 | 3/3 |
| 平均工具调用 | 1.31 |
| 工作流 P50/P95 | 43 / 139 ms，含本机状态夹具和模拟 I/O |
| 故障恢复 | 2/2，检查点重建和超时后安全重试 |

输入刻意包括错误工具、未知工具、缺参数、幻觉 ID、注入身份以及超时。固定响应轨迹反映执行器拒绝和计量行为。真实模型的意图与工具准确率仍需另行测量。

## 独立数据库 E2E

GitHub CI 新增 MySQL 8.4、Redis 7 和 Chromium 作业。测试通过启动的 Spring Boot 与 Vue 实例执行真实登录、四种工作流、跨账号拒绝、重启保留审批、并发确认、写入验证和浏览器刷新恢复。DeepSeek 默认由本地 HTTP 模型夹具代替，业务数据库和浏览器流量保持真实。

本机准备独立 MySQL 测试库名（必须以 `_test` 结尾）和 Redis，使用现有配置变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`。空闲端口 8080、5173 和 18081。脚本会创建随机测试账号和学习数据，测试库应单独准备和清理。从仓库根目录运行：

```sh
mvn -B -f backend/pom.xml package -DskipTests
cd frontend
npm ci
npm run build
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
cd ..
node tests/c8-e2e.mjs
```

本地显式设置 `C8_LIVE_DEEPSEEK=true` 和 `DEEPSEEK_API_KEY` 可切换供应商联调。CI 会拒绝该模式。运行输出记录数据版本、通过的检查、供应商返回的模型、参数、工具名、延迟和 token 用量，实际费用按账号账单计。输出不含凭证或原始提示词。模型夹具运行的供应商成本为零。
